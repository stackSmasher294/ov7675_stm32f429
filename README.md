# ov7675_stm32f429
Streaming a video from a OV7675 camera into a STM32F429_DISC1 dev board and rendering the video on the onboard TFT LCD.

The camera module streams an image of size 320 X 480 (RGB565) to STM32F429, using its GPIOs to read the DVP interface of OV7675.
This camera module takes the 6 MHz XCLK, generated by TIM2 (since MCO1 is not available), upconverts it into 6X using the onchip PLL. This is done so that a high speed clock does not skew on my rather crudely setup using a prototyping PCB.

For each HSYNC pulse, the row data is copied into a scratch buffer (located in the CCM ram), which is later copied into a bigger frame buffer (located on the onboard 8MB SRAM), after transposing and downconverting the row data to 320 x 240.

### Connections:

|STM32F429                          |OV7675                         |
|-------------------------------|-----------------------------|
|SCL|PA8                   
|SDA|PC9  
| VSYNC | PD5
| HSYNC | PD4
|PCLK | PC12
|XCLK | PA5
| DATA[0:4] | PE[2:6]
|DATA[5:6] | PB[3:4]
| DATA[7]| PB7
|PEN/RST | PC8
|PDN | PC11               


> Note: STM32F429 has a dedicated DCMI (Digital Camera Interface) to read DVP signals. Unfortunately the relevant pins are occupied by the SRAM signals on the DISC1 board.  
> Also, on this board, none of the GPIO ports have all the 8 pins free, therefore an efficient single register read is not possible. I have to bit-shuffle across Port E and B
